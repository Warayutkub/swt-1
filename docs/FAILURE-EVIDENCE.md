# หลักฐานว่าเทสต์จับความผิดพลาดได้จริง

เทสต์ที่เขียวตลอดไม่ได้พิสูจน์อะไร — **มันอาจไม่ได้ตรวจอะไรเลยก็ได้**
เอกสารนี้จึงจงใจทำให้โค้ดผิด แล้วเก็บผลรันจริงมาแสดงว่าเทสต์ตัวไหนจับได้

ทุกผลลัพธ์ในหน้านี้ **คัดลอกมาจากการรันจริง** ไม่ได้เขียนขึ้นเอง

| | |
|---|---|
| สภาพปกติ | `107 passed, 2 skipped, 1 xfailed` · coverage 100% · exit code **0** |
| จำนวนกรณีที่ทดสอบ | 7 (บั๊กจริง 1 + จงใจทำพัง 6) |

---

## กรณีที่ 0 — บั๊กจริงที่เจอจากการเขียนเทสต์เพิ่ม ⭐

**กรณีนี้ไม่ได้จงใจ** เกิดจากการไล่เพิ่มเทสต์กรณีผิดพลาดแล้วเจอว่าระบบทำงานไม่ถูก

### อาการ

ข้อความที่มีแต่ช่องว่าง เช่น `09:00⇥มะลิ⇥"   "` **หายไปเงียบ ๆ**
และ log ยังบอกสาเหตุผิดว่า "รูปแบบไม่ถูกต้อง" ทั้งที่มันแค่ว่างเปล่า

### สาเหตุ

```python
line = raw.rstrip()        # ตัดช่องว่างท้ายบรรทัดทิ้งก่อนตรวจรูปแบบ
```

```
"09:00<tab>มะลิ<tab>   "   ->  rstrip()  ->  "09:00<tab>มะลิ"
                                              └─ เหลือ tab เดียว ไม่ตรงรูปแบบ
                                                 -> ถูกทิ้ง + log ผิดสาเหตุ
```

### ผลรันตอนเทสต์ยังแดง

```
>       assert len(messages) == 2
E       AssertionError: assert 1 == 2
E        +  where 1 = len([Message(timestamp=datetime.datetime(2026, 9, 1, 9, 5),
E                          sender='ฉัน', text='สวัสดี', kind=<Kind.TEXT: 'text'>)])

------------------------------ Captured log call ------------------------------
WARNING  chatlog.parser:parser.py:102 ข้ามบรรทัดที่ 2 เพราะรูปแบบไม่ถูกต้อง: 09:00	มะลิ

FAILED tests/unit/test_parser.py::test_ข้อความที่มีแต่ช่องว่างยังนับเป็นข้อความ
1 failed, 26 passed, 1 skipped, 1 xfailed in 0.10s
```

สังเกตว่า pytest แสดง **log ที่เกิดขึ้นระหว่างเทสต์** ให้ด้วย ทำให้เห็นสาเหตุทันทีโดยไม่ต้องไปไล่โค้ด

### วิธีแก้

```python
line = raw.rstrip("\r\n")   # ตัดเฉพาะอักขระขึ้นบรรทัดใหม่
```

ช่องว่างส่วนเกินถูกตัดทีหลังตอนประกอบเนื้อความแทน

### ผลหลังแก้

```
107 passed, 2 skipped, 1 xfailed
TOTAL  240 stmts  0 miss  100%
```

> **นี่คือเหตุผลที่ต้องเขียนเทสต์กรณีผิดพลาด** — โค้ดนี้ผ่านเทสต์ 89 ตัวและ coverage 100%
> มาก่อนหน้านี้ แต่ยังมีบั๊กซ่อนอยู่ เพราะไม่เคยมีใครลองป้อนข้อความว่างเข้าไป

## กรณีที่ 1 — ขยับขอบเขต "ดึก"

**แก้:** `src/chatlog/rules.py` → `NIGHT_END = time(5, 0)` เป็น `time(6, 0)`

```
E       assert True is False
E        +  where True = is_late_night(datetime.datetime(2026, 9, 1, 5, 0))
E        +    where datetime.datetime(2026, 9, 1, 5, 0) = datetime(2026, 9, 1, 5, 0)

FAILED tests/unit/test_rules.py::test_is_late_night[ตีห้าตรง-หมดช่วงดึก]
1 failed, 106 passed, 2 skipped, 1 xfailed in 0.27s
```

**อ่านผลนี้ยังไง** — พังแค่ **1 ใน 6 เคส** ของเทสต์เดียวกัน เพราะ `parametrize` แยกเป็นคนละเทสต์
และชื่อในวงเล็บบอกทันทีว่าเคสไหน นี่คือประโยชน์ของ `pytest.param(id=...)`

## กรณีที่ 4 — เขียน JSON เป็นรหัสแทนภาษาไทย

**แก้:** `src/chatlog/report.py` → `ensure_ascii=False` เป็น `True`

```
E       assert 'มะลิ' in '{\n  "\\u0e0a\\u0e48\\u0e27\\u0e07\\u0e40\\u0e27\\u0e25\\u0e32":
E                          "2026-09-01 \\u0e16\\u0e36\\u0e07 2026-09-02", ... }'

FAILED tests/unit/test_report.py::test_ภาษาไทยไม่ถูกแปลงเป็นรหัส
1 failed, 106 passed, 2 skipped, 1 xfailed in 0.28s
```

**อ่านผลนี้ยังไง** — โปรแกรมยัง "ทำงานได้" ไฟล์ยังเขียนออกมา JSON ยังถูกต้องตามมาตรฐาน
แต่**มนุษย์อ่านไม่ออก** เทสต์จับเรื่องคุณภาพที่ไม่ใช่แค่ "พังหรือไม่พัง" ได้ด้วย

## กรณีที่ 5 — โยน error ถูกชนิด แต่ข้อความผิด

**แก้:** `src/chatlog/summarizer.py` → เปลี่ยนข้อความ error จากที่มีชื่อตัวแปร เป็นแค่ `"ไม่พบคีย์"`

```
E       AssertionError: Regex pattern did not match.
E         Expected regex: 'CHATLOG_API_KEY'
E         Actual message: 'ไม่พบคีย์'

FAILED tests/unit/test_summarizer.py::test_ไม่มีคีย์ต้องโยน_error
1 failed, 106 passed, 2 skipped, 1 xfailed in 0.27s
```

**อ่านผลนี้ยังไง** — `MissingApiKeyError` ยังถูกโยนเหมือนเดิม **ถ้าเช็คแค่ชนิดของ error เทสต์จะผ่าน**
ที่จับได้เพราะใส่ `match=` ไว้ด้วย

นี่คือคำตอบของคำถามว่า *"ทำไมต้องใส่ `match=`"* — เพราะ error ที่บอกไม่ครบ
ทำให้คนใช้งานแก้ปัญหาไม่ถูก ทั้งที่โปรแกรม "ทำงานถูก" แล้ว

## กรณีที่ 6 — เทสต์ผ่านหมด แต่ผลรวมยังแดง

**ไม่ได้แก้โค้ดเลย** แค่รันเทสต์ไม่ครบชุด (เหมือนกรณีที่มีคนลบไฟล์เทสต์ทิ้ง)

```bash
python -m pytest tests/unit/test_rules.py --cov
```

```
Name                        Stmts   Miss Branch BrPart  Cover
-----------------------------------------------------------------
src\chatlog\stats.py           43     43     10      0     0%
src\chatlog\summarizer.py      22     22      2      0     0%
-----------------------------------------------------------------
TOTAL                         240    173     52      0    25%

FAIL Required test coverage of 85.0% not reached. Total coverage: 25.00%
21 passed in 0.11s
```

```
exit code = 1        <-  ทั้งที่บรรทัดบนเขียนว่า 21 passed
```

**อ่านผลนี้ยังไง** — นี่คือกรณีที่สำคัญที่สุดในเอกสารนี้

```
เทสต์ผ่านหมด 21 ตัว     แต่     exit code = 1
                                     ↓
               ระบบอัตโนมัติ (CI) จะถือว่างานนี้ "ไม่ผ่าน"
```

**เกณฑ์คุณภาพทำให้งานไม่ผ่านได้ ทั้งที่ไม่มีเทสต์ตัวไหนพังเลย**
เพราะ "ไม่มีเทสต์พัง" กับ "ทดสอบครบพอ" เป็นคนละเรื่องกัน
